螺壳体检

在空闲时只读地查一遍这台 Mac：空间去向、会重建的缓存、卸载残留、久未动的项目、重复和久未打开的大文件，以及常驻项、进程、权限、基础安全设置和病毒。是不是垃圾、能不能删由确定的规则决定；结果经 agent 告诉用户，删除只执行用户在卡片上点过的方案，并移到废纸篓。

仓库 luoke-audit（Swift 包，两个程序 luoke-audit、luoke-audit-serve）· 版本 0.1.0，规则包 0.1.0，按代码 6fa5b14 核对 · 不在 v1 首发中；接进螺壳（luoke-core#27）在 beta1 之后 · 只支持 macOS 26.2 及以上

职责

  • 查的时候只读，不改任何东西。能用元信息（大小、时间、inode、签名、链接数）判断的不读内容；要内容的（重复文件的哈希、明文凭据、散落的密钥）只在本机读，内容不进报告、日志和卡片。
  • 每条发现带结论（放心删 safe / 要确认 confirm / 仅供参考 info）、类别、严重度和依据。只有会重建的缓存能得到"放心删"。
  • 检查没跑成记成"没扫描"并写原因，不算没有发现。
  • 不主动找用户：没有通知、没有菜单栏图标，要说的事放进 outbox，由 agent 挑时机。
  • 不带模型。病毒扫描用随包的 ClamAV 和 YARA（特征扫描，不是模型）。

运行形态

程序行为
luoke-audit「螺壳体检.app」的主程序，用户给「完全磁盘访问」的就是它。扫描、出方案、执行方案、自动清缓存都在它里面；从不开 socket。空闲任务 scan --this-mac、update --this-mac 起它；agent 的每个请求起一次 luoke-audit mcp（标准输入一条 JSON-RPC，标准输出答复，答完就退出）
luoke-audit-serve只管给 agent 的 socket ~/.luoke-audit/run/agent.sock，不读不动用户的文件，不要完全磁盘访问；只链接 AuditSocket，不含检查和清理的代码。每个 POST /mcp 以"自己负责"（responsibility_spawnattrs_setdisclaim）起同一文件夹里的 luoke-audit mcp，只传 0、1、2 三个描述符，等 290 秒。每 300 秒（--quick-every）起一次 luoke-audit scan --quick 看新下载的
  • 谁起：空闲任务由主控按配件清单的 jobs 起（每天一次，接着电源）。luoke-audit-serve 要常驻，配件清单里还没有起它的字段，目前要手动起。
  • 装好的包只认 --this-mac：在 .app 里运行时，--home、--data、--tmp、--projects、--tool-dir、--fixture、--clock-start 和 fixture 子命令都拒绝；扫描工具只用包里的，不找 Homebrew 的（那些文件夹用户可写，会借到完全磁盘访问）。
  • --this-mac 查哪里：家目录、本用户的临时目录（DARWIN_USER_TEMP_DIR），项目目录取 ~/Developer、~/Projects、~/Documents/GitHub、~/code、~/src、~/repos、~/workspace 里存在的；数据放 ~/.luoke-audit。
  • 一次一轮：每个数据目录用 round.lock 保证空闲任务和 agent 叫的那一轮不重叠；快速扫描另有 quick.lock；一个数据目录只能起一个 luoke-audit-serve（serve.lock）；一份方案同时只在一个进程里执行（plans/<编号>.lock）。
  • 跑得轻：scan、update 以 utility 优先级运行（磁盘 I/O 同档，起的 clamscan、yara、git 也是）；只在 iCloud 的文件不读（读会触发下载）。外部命令都带超时，超时连进程组一起杀。
  • 被打断：收到 SIGTERM 时停在做完的那一步、保存报告、退出码 0；没来得及查的规则沿用上一轮的发现并在 skipped 里注明，量过的留给下一轮。被打断的一轮不自动清缓存。
  • 快速扫描（scan --quick）：只在接着电源、不在低电量模式、内存压力不高（kern.memorystatus_vm_pressure_level ≤ 1）时跑；FSEvents 日志显示下载或桌面有改动才扫，只跑病毒扫描，用精简库，结果并进上一轮的报告；整轮在跑就不看。还没有完整的一轮时不做。

检查什么

一轮按顺序跑 19 条规则，每条记耗时（ruleSeconds）。下表按类别合并；"结论"是规则给的。

病毒扫描

  • 扫什么：下载文件夹里 30 天内来的文件（按修改时间或加入时间）、Spotlight 记着在家目录别处下载的（kMDItemWhereFroms）、下载来的应用里的程序（Contents/MacOS 全部，另加至多 50 个可执行文件）、本用户 LaunchAgent 运行的程序；一轮最多 2000 个。
  • 只扫新的：扫过的记在 malware_scanned（路径、inode、大小、修改时间、当时认出的）；没变的 7 天后再扫，病毒库更新后 3 天内来的文件用新库再扫；没有要扫的就不起 clamscan。
  • ClamAV：--max-filesize=100M --max-scansize=400M --alert-exceeds-max=yes，太大的报 malware.too-large；读不了的文件不交给扫描器，下一轮再看；文件名带控制字符的单独报 malware.odd-name。整轮 clamscan 限 30 分钟、YARA 15 分钟。
  • YARA：自带两条规则（反弹 shell、伪造的系统密码对话框），加上 macOS 自带 XProtect 的规则（取版本新的那份；编不过时只用自带的），发现记成 malware.yara.xprotect.<规则>。
  • 精简库：快速扫描用的库由 sigtool --unpack 拆开后去掉 Win.、PUA.Win. 开头的特征和 PE 的节、导入表哈希，每个库文件一个子目录、只重做变了的；快速扫描扫过的记成 +quick，下一次整轮用全库再扫。
  • 病毒库更新（update）：每天最多一次；freshclam 在克隆出的临时目录里下载，sigtool --info 逐个校验通过才换库，任何一步失败保留旧库；被上游限流时保留 freshclam 的冷却状态。库超过 14 天没更新报 malware.stale-db，照样扫。

增量

  • 量大小：每个文件夹和它下面两层 ≥ 1 MB 的子目录记下 FSEvents 事件号、inode、大小；下一轮回放日志，没改动、inode 没变、真正量过不到 7 天的沿用，被碰过的只重量改过的子目录。日志换了或丢了细节就全量。
  • 临时目录、老项目：同样按 FSEvents 沿用上次的结论（temp_entries、project_state），最长 7 天。
  • 遍历用 getattrlistbulk，不跟符号链接，不进挂在里面的别的卷。新装应用和常驻项的签名结果按文件记下，最多沿用 7 天。

清理

  • 方案：audit_plan 或 outbox 卡片从上一轮的发现出方案（最多 30 项），每项可选移到废纸篓、先不动、以后别提，重复文件另有换成克隆。放心删的默认移到废纸篓，要确认的默认先不动。"仅供参考"的不进方案。方案存在 plans/，30 天后删掉。
  • 能进方案的：缓存、残留、临时目录的成批前缀、干净的久未动项目、久未打开的大文件、重复文件、本用户指向不存在程序的 LaunchAgent 和新出现的本用户 LaunchAgent、病毒库或 YARA 认出的文件。目标只能在家目录或临时目录里面（不能是家目录、临时目录、项目目录本身）。
  • 执行（audit_apply）：没有 ai.luoke/user-action 就拒绝；只执行本工具出过的方案、只接受方案里列的选项，没送的项当"先不动"。每个目标再核对：还在、不是链接、设备号和 inode 没变、在家目录或临时目录里、父目录本用户可写、里面没挂别的盘、查过以后没改过（缓存除外；未来时间不算；核对总共最多 2 分钟）；久未动的项目再问一次 git。核对不上的跳过并写原因。
  • 怎么删：移到废纸篓（trashItem），能从废纸篓放回。LaunchAgent 先 launchctl bootout 再移配置。重复文件移走前确认要留的那份还在且内容相同；换成克隆前逐字节再比一遍，几份都留着。
  • 要管理员密码的不删：系统目录里的项答"在系统目录里，要密码，这一版还不能删"；系统级常驻项、登录项、crontab 的卡片只给去哪里关的说明或打开系统设置。
  • 缓存自动清：用户在卡片上点「以后缓存自动清」（audit_autoclean）后，定时的一轮查完就清掉查到的会重建的缓存：只限上面那张缓存清单、只在它的固定位置、不经链接、它的工具在运行时留到下一轮；Go、uv、npm 用工具自己的清理命令（指向报出的那个文件夹），其余直接删文件夹，不进废纸篓。agent 叫的那一轮、快速扫描、被打断的一轮都不清。每次清完记一条 auto-done（清了哪些工具、多大，部分清了或没清成也报），卡片不给撤销，给「以后别自动清」。
  • 除缓存外，任何删除都要用户在卡片上点。自动清不覆盖安装包、下载文件夹里的重复文件和临时文件夹，没有一键放回的工具，也没有按类别关自动清的开关。

接口

给 agent 的 MCP 工具

按 agent 工具协议（版本 1，MCP 2026-07-28 的无状态子集：server/discover、resources/list、resources/read、tools/list、tools/call），在 ~/.luoke-audit/run/agent.sock 上 POST /mcp，请求体至多 1 MB。卡片是 A2UI v0.9（目录 ai.luoke/a2ui/agent/1）。不支持订阅。

工具只读参数 → 答复
audit_status是— → 上一轮的时间和耗时、三种结论各多少、放心删能腾出多少、病毒库版本和日期、没查成的规则、缓存是否自动清、是否正在查；带卡片
audit_findings是可选 verdict（safe / confirm / info）、category、limit（1–50，默认 20）→ 发现列表和卡片；标成"以后别提"的不列
audit_scan_now是— → 另起 luoke-audit scan --for-agent，马上答复；这一轮不自动清缓存；已经在查就说一声
audit_plan是可选 scope（all / cache）→ 方案和确认卡片
audit_apply否（destructive）plan_id、choices → 移了、克隆了、部分处理、已不在、没动的各几项；什么都没剩时 done: true
audit_ignore否finding_id → 以后不再报这一条
audit_autoclean否enable → 开或关缓存自动清
audit_reveal是finding_id → 在访达里选中；东西不在了答 stale。标 ai.luoke/where: mac
audit_open_settings是grant（隐私与安全性里的某项权限，或「登录项」）→ 打开系统设置对应页。标 Mac
outbox_ack是id、state（shown / answered / dismissed）；answered、dismissed 的不再出

非只读的工具没有完整的 ai.luoke/user-action（surfaceId、componentId、at）答 needs_user_action。其他错误码：not_ready、stale、invalid、failed。发现的编号跨轮稳定：规则名加规范化路径（或规则给的键）的哈希。卡片里家目录下的路径写成 ~/…。

打包

  • scripts/package_app.py 拼「螺壳体检.app」：bundle id ai.luoke.audit，LSUIElement，最低 26.2。Contents/MacOS 里有 luoke-audit、luoke-audit-serve（ai.luoke.audit.serve）和 clamscan、freshclam、sigtool、yara；它们要的库在 Frameworks，路径改成 @rpath；ClamAV 的 RAR 支持运行时由 LD_LIBRARY_PATH 指到 Frameworks。
  • 由内向外签名，hardened runtime，没有 entitlements（临时签名时扫描工具带"可以载入别人签的库"，正式签名不许有）；可选公证。Developer ID 证书和公证条目由出版机器给，脚本不带凭据。
  • Resources 里有去掉草案标记的配件清单、bundled-tools.json（每个随包程序和库的版本、来源、SHA-256）、许可证（ClamAV 为 GPLv2）和第三方说明。
  • 打完必核对：签名完整、都是 hardened runtime、没有 get-task-allow、没有包外的库路径、luoke-audit-serve 里没有 AuditCore / AuditService 的代码、第三方库只有允许清单里的、包里的 luoke-audit 不收开发参数，再用包里的 clamscan 和 YARA 真扫一个 EICAR 测试文件。Swift 包不加第三方依赖（测试里也查）。

已知限制

  • 没接进主控：配方里没有两个生成任务，配件清单没有常驻起 luoke-audit-serve 的字段。
  • 没有模型参与：explain、identify 只有提示词和评测，程序里还没调用；认不出的目录不会被起名。
  • 不写记忆。
  • 要管理员密码的删除没做（系统目录里的残留、旧版 Homebrew 只报不删）；没有方案按要不要密码拆成两份。
  • 没有报告页，只有终端的 luoke-audit report 和 agent 的卡片。
  • 自动清只覆盖会重建的缓存，且要用户先点一次；没有放回已清项的工具，也没有按类别关的开关。缓存清了不能撤销。
  • 配件清单里 scan 标 uses_model: true、explain 标 main: true，与程序现状不符。
  • 程序报的版本是 0.1.0-dev（version 和 MCP 的 serverInfo），配件清单和 Info.plist 是 0.1.0。
