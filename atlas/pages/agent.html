agent「螺壳」

螺壳里唯一主动找用户的组件。它把记忆的提问和建议、各工具要报的事合并成卡片和简报，挑时机告诉用户，并代表用户调用工具声明的能力。当前版本不使用模型。

仓库 luoke-agent · 核心 0.0.1 · 自带 luoke_mem 0.23.1 · 不在 v1 首发中

职责

  • 从记忆读取待问的问题和建议（asks），从各工具读取待报事项（outbox），统一排序后在窗口、通知和简报中呈现。
  • 把用户的回答交回来源：交给记忆的经 Memory.reply，交给工具的经工具协议调用对应能力。
  • 只在用户点按卡片时发出会改动数据的调用。不自行推断用户信息，也不替工具执行动作。

进程模型

部分实现职责
壳Swift 应用（macOS 14+），菜单栏常驻，依赖 A2UI 渲染包菜单栏、窗口、系统通知、卡片渲染、上报用户是否在场
核心Python 包 luoke_agent（仅标准库），运行在主控自带的 Python 上读记忆、连接工具、事项库、决定何时说
  • 启动：主控按配件清单（resident: true）拉起壳；壳以 python -m luoke_agent serve --home H --memory M --parent-pid P 启动核心，标准错误追加到 <home>/logs/core.log。
  • 存活：核心意外退出时壳会重启它，间隔从 2 秒翻倍到 60 秒；核心每 2 秒检查父进程，壳退出时随之退出。
  • 壳与核心之间：<home>/run/agent.sock 上的 HTTP/1.1，见「界面协议」。
  • 轮询：核心每 5 秒一个周期；工具 outbox 每 60 秒读一次，记忆和主控每 300 秒各读一次，简报到点前会额外读一次记忆；窗口打开时立即把全部来源读一遍。一个来源出错不影响其他，暂时不在运行的来源卡片先收起，回来后照旧。
  • 使用的主控接口：GET /accessories 发现已安装的工具（只认 capabilities.protocol 为 1 且有 socket 的，排除自己）；核心每次启动时经 GET /tasks 取主控内置的 luoke_mem 路径，取不到或导入失败时用自带的副本。

工具协议

工具在配件清单的 capabilities 中声明协议版本（1）、socket 路径、可报事项（reports[]：kind、title、默认 urgency）和动作（actions[]），并在自己的 Unix socket 上提供 MCP 子集。完整规格见 luoke-agent/docs/工具协议.md。目前没有已发布的配件在清单中声明 capabilities：邮件助手的实现默认关闭，agent 实际只有记忆一个来源。

传输

  • 每个请求一条连接：POST /mcp，请求体为一条 JSON-RPC 2.0 消息，上限 1 MB；MCP 协议版本 2026-07-28，在 params._meta 中携带。
  • 超时：连接 10 秒；读 outbox、列工具 10 秒；只读调用 30 秒；写调用 300 秒。socket 不存在视为工具未运行，不算错误。

方法

方法用途
server/discover协议版本和服务能力
resources/list、resources/read读 outbox：luoke://<配件>/outbox，内容 {items:[…]}
tools/list能力列表，带 readOnlyHint、destructiveHint
tools/call调用能力；写调用必须在 _meta 中带 ai.luoke/user-action（{surfaceId, componentId, at}），否则工具返回 needs_user_action
  • outbox 事项字段：id、kind、urgency、deadline、expires、created、why_now、title、summary、card。outbox 是一份完整状态，上一轮有、这一轮没有的事项视为撤回。
  • 调用结果的 structuredContent 可带 card（更新原卡片）、done（事项完成，卡片保留 30 分钟以便撤销）、drop（立即撤下）。失败码：needs_user_action、invalid、not_ready、needs_setup、stale、failed。
  • 撤销是结果卡上的一个写按钮，走同一条点按路径。

卡片（A2UI）

  • A2UI v0.9，目录 ai.luoke/a2ui/agent/1，组件限于 Text、Row、Column、List、Card、Divider、Button、CheckBox、ChoicePicker、TextField、DateTimeInput、Icon。
  • 校验：根组件存在、可达组件 ≤ 200、累计 ≤ 1000、无环、单父、绑定路径存在、文字 ≤ 2000 字；未通过校验的卡片改为纯文本卡。
  • agent 自己处理的动作：agent.open_url（仅 https，按钮文字后附域名）、agent.dismiss、agent.remind。

与记忆的交互

  • 以 Memory(path, tool="luoke-agent") 打开记忆；文件不存在时不创建，遇到版本过新的库时提示更新。
  • 读取 asks(status=["open"])，该不该问、每天几条由记忆决定；带 about_note 的问题附上该理解最新的 3 条依据原文（来源、日期、每条 120 字以内），没有时显示 ask 的 evidence。记忆的提问和建议 urgency 默认为 normal，走简报。
  • 回答经 reply(ask_id, choice, text) 交回：
卡片按钮 → choice
处理习惯等是非类建议好 → useful · 不用 → useless · 别再提 → never
信息性建议知道了 → useful · 别再提 → never
关于某条理解的问题对 → yes · 不对 → no · 以前是，现在不是 → past · 按我改的 → revise · 以后再说 → later（记忆把问题记为 later，7 天后由反刍重新提出）
自由问题交回 → answer · 以后再说 → later

何时说

  • 排序：urgency（urgent、normal、low）→ deadline → 首次出现时间。
  • 每类的方式（modes）：now、brief、window、off；未设置时 urgent 为 now，其余为 brief。
  • 急事：用户在 Mac 前（120 秒内有上报、未锁屏、屏幕未睡、空闲 < 180 秒）时立即通知，不受免打扰时段限制。
  • 简报：第一件待简报的事项（normal；只有 low 时距上一份 low 简报 ≥ 24 小时）出现后计时 60 分钟，到点后等用户在场且不在免打扰时段才发；每份含全部 normal，最多附 2 件 low；通知正文列前 3 个标题；上一份未打开窗口时新的一份静音。
  • 窗口：窗口打开时，现有事项都算看过，不再为它们发通知。
  • 少说：同一类连续 3 次没有回应，从 brief 降为 window，并给出一张"以后只放在窗口里"的卡片。
  • 清理：过期事项撤下；完成的卡片 30 分钟后撤下；完成或撤回超过 30 天的记录删除。

数据和文件

位置内容

设置默认值：brief_minutes 60、away_seconds 180、ignore_limit 3、quiet 无、modes 空。

安全

  • 写调用只在 POST /action（用户点按）时发出，并附 user-action；方案编号、链接、问题编号等写死的值只认核心保存的卡片声明，不采用界面送来的同名值。
  • 工具和记忆送来的文字一律按纯文本渲染；每张卡片带来源前缀，按钮只转给出这张卡片的来源。
  • socket 只靠文件权限（目录 700、文件 600）限定在当前账户内，不核对调用方身份。

已知限制

  • 没有对话，不使用模型；outbox 靠轮询，未实现订阅。
  • 写调用只看 tools/list 的 readOnlyHint，不对照清单里声明的 actions。
  • deadline 只影响排序，过期不会标记；off 与 window 效果相同。
  • 从不发送 outbox_ack state:"shown"，工具无法据此停止自己的通知。
  • 设置没有界面；卡片上用户改过的选项只存在壳里，壳重启后丢失；core.log 不轮转。
  • 简报通知的正文包含事项标题。
  • 自由问题（不针对某条理解）的"以后再说"记忆不接受，卡片会显示"这条已经变了"并关闭；记忆目前不产生自由问题。
  • 核心只在启动时取一次主控的 luoke_mem 路径；主控升级后需重启核心才换用新的。
