深度搜索

给 Mac 上用户选的文件夹和照片图库建索引，按字词和按意思找回来。没有自己的界面，入口在 agent。本章描述登记的设计：主线目前只有说明文件，还没有代码。

仓库 luoke-search · 规划中，未发布 · 跟随 agent（v1.x），不在 v1 首发中

职责

  • 第一版搜本机文件：文档（txt、md、rtf、doc、docx、odt、html、xlsx、pptx、csv、tsv，含 GBK 编码的文字文件）、PDF（逐页读，扫描件按页 OCR）、截图（读其中的字）、图片、视频（关键帧和音轨）、录音；经 PhotoKit 读照片图库（需用户允许）。不搜代码。
  • 第二步经记忆读记录和依据原文、打字记录，经邮件助手的读取接口读邮件；自己只存向量和关键词，不重复存原文。
  • 只读用户的文件，不改、不移动、不上传；不主动找用户，只经 agent 的 outbox 报两类事。

运行形态

  • 常驻的后台 .app（不出现在程序坞），由主控安装、登录时拉起；bundle id 拟为 ai.luoke.search。同一个可执行文件也是命令行 luoke-search。只支持 macOS 26.2 及以上。
  • 没有界面：没有菜单栏图标、窗口或快捷键面板。用户在 agent 的对话里提问，agent 调用 MCP 工具，把结果画成卡片（标题、命中片段、出处的页码或时刻），点按后在 Mac 上打开；要用户定的事（搜哪些文件夹、是否加入照片图库）也由 agent 的卡片询问。
  • 建索引分两步：读取（取文字、OCR、抽关键帧、切声音）由本工具完成，完成即可按字词搜；算向量找主控，主控不在或忙时记为"等向量"，以后补。
  • 按字词搜用 SQLite FTS5（unicode61 表，另加给中文、日文用的 trigram 表），按意思搜比余弦，两者混合排序；查询中的类型词（"截图""照片"等）给对应类型加分，停用词不当关键词。

接口

给 agent 的 MCP 工具

按 agent 工具协议（版本 1），在 ~/.luoke-search/run/agent.sock 上提供；luoke-search mcp 在标准输入输出上提供同一组工具。

工具只读做什么
search_query是参数 query，可选 kinds、since / until、limit；答复结果列表（编号、类型、标题、出处、页码或时刻、命中片段、为什么对得上、分数）、partial（还在建索引或缺向量时为真）和一张 A2UI 结果卡片
search_open是按结果编号打开并跳到那一页或那一刻，或在访达中显示
search_status是已索引多少、还在等什么、主控能否算向量
search_settings是查看设置；给出要改的内容时返回一张确认卡片（方案）
search_settings_apply否执行用户在卡片上点按的方案：搜哪些文件夹、跳过哪些、是否加入照片图库、用电池时是否建索引
search_open_system_settings是打开系统设置中对应的隐私页
  • outbox luoke://luoke-search/outbox：needs-access（normal，需要用户允许读某个文件夹或照片图库）、index-ready（low，第一遍索引完成）。不推送搜索结果。
  • 命令行 luoke-search：index、search、open、status、settings、eval、mcp，与 MCP 工具一一对应，--json 输出与 MCP 答复同格式；--index 指定索引目录，LUOKE_HUB_SOCKET 指定主控。

使用的主控接口

  • 嵌入任务 POST /tasks/<任务>/v1/embed：满 768 维、L2 归一化的向量，带 vector_space（变了只重算向量、不重读文件）；查询以用户在等发送，建索引以后台发送；被挡回时按 retry_after_ms 等待。参数只从 GET /tasks 读。
  • 任务名：登记为 luoke-search.embed；当前主线配方中仍为 digup.embed（所属配件 digup），未分配到任何档，各档答 unsupported。
  • 主控的空闲任务支持清单中的 exec（Contents/MacOS 下的可执行文件名），供不带 Python 的配件使用。

数据

~/.luoke-search/数据目录（700），排除出 Time Machine

run/agent.sockMCP socket
  • 名字像密码、密钥、证书、令牌的文件一律跳过，不读内容；结果、卡片、outbox 中不放凭证。
  • 向主控只送文字、图片和声音的字节，不送路径。日志只记元数据，不记搜索词、片段和文件内容。
  • 第一版不读也不写记忆，搜索词不写进记忆。

故障

  • 主控不在、忙或任务不可用：照常读取文件、按字词搜，向量以后补；不退回任何自带模型。
  • 还在建索引或缺向量时，答复带 partial 和一句说明。

已知限制

  • 图片和声音的向量要等主控换上带新 mlx-vlm 的引擎包；在那之前图片、视频、录音只能按文件名和 OCR 的字找。有了图片和声音才发布。
  • 没有拒答门槛：语料里没有答案时多半仍给出不相干的结果；门槛在这类题有评测数字后再定，在那之前答复不表示"有把握"。
  • 邮件读取接口、与 agent 的分工（谁判断要搜、手机端要什么、A2UI 目录没有图片组件时缩略图怎么办）待商定。
