数据流

一封邮件

sequenceDiagram
  participant M as 邮箱（IMAP）
  participant L as 邮件助手
  participant C as 主控
  participant R as 记忆
  participant U as 用户
  L->>M: 同步收件箱
  L->>C: triage（用户在等或后台）
  C-->>L: 建议、摘要、截止日期、可疑
  L->>M: 标已读；按确定的习惯归档或加标签
  L->>R: 记录 mail-read、mail-auto
  U->>L: 在"今日处理"中撤销或改建议
  L->>R: 记录 mail-override、mail-undo-auto
  R->>C: 空闲时归纳话题和习惯
  R-->>L: 建议"以后都这样？"
  1. 后台循环按间隔同步，新邮件逐封交给主控的 luoke-mail.triage，"关于用户"取自记忆中比较确定以上的事实和习惯。
  2. 分拣后自动标已读（一条可整批撤销的操作记录），并执行记忆中确定、可自动执行的处理习惯；结果进入"今日处理"。
  3. 用户的操作（改建议、亲手归档、撤销自动处理）写成记录。
  4. 记忆的归纳任务从这些记录形成处理习惯和话题，向邮件助手提出建议；用户同意后习惯成为确定，下一次同步开始自动执行。

打的字

sequenceDiagram
  participant E as 打字引擎（沙盒）
  participant P as 个人化组件
  participant C as 主控
  participant R as 记忆
  E->>P: score（候选）
  P->>C: luoke-ime.rerank
  C-->>P: logprobs
  P-->>E: 分数（引擎据此重排）
  P->>R: ime-commit（上屏 + 前文，凭证已遮去）
  R->>C: 空闲时归纳常用说法和话题

提问和建议

  1. 记忆的反刍在每次归纳任务的开头和结尾运行，生成提问（每天 ≤ 2）和建议（每天 ≤ 3），写入 asks。
  2. agent 每 300 秒读取一次，在窗口、通知或简报中展示；与邮件有关的建议也在邮件助手的记忆页中展示。
  3. 用户的回答经 Memory.reply 交回，记忆据此定档。

外部工具

高级用户可开启主控的本机端点，让 pi 等工具通过 OpenAI 兼容接口使用本机模型，包括用户自己登记的模型。这些请求与配件请求一起由主控调度，按"用户在等"处理。
