# 螺壳输入法 luoke-ime

- 仓库：[`luoke-ime/`](../luoke-ime)；进度：`luoke-ime/STATUS.md`；设计：`luoke-ime/docs/设计.md`
- 本页由 luoke-ime 的会话维护。

## 是什么

macOS 输入法。壳只管按键、候选窗、上屏和沙盒，出什么候选全部交给输入法引擎（独立的子进程，经标准输入输出说 JSON 行，在 Seatbelt 沙盒里按声明放行）。

- 自带的输入法引擎：小鹤双拼、全拼（苹果自带的转换引擎和 RIME 出候选，本地模型按前文逐词重排，博客语料首选准确率约 90%，苹果单独 78.8%）、最小示例。
- 个人化组件（`engines/personal`）：把上屏写进记忆（2026-10-10 装上）；模型打分从小鹤、全拼搬进来，它们经壳转问它（2026-10-11）；联想（上屏后按 ⇥，候选来自用户自己写过的和模型续写）。
- 计划：读 luoke-mem 归纳的理解（常用说法、关注的话题）来做带个人化的打分和联想；语音输入（快捷键引擎）。

## 对外提供

- 现在：输入法本身；把用户上屏的文字写进记忆（`ime-commit`、`ime-correction`、`ime-forget`）。经输入法上屏的都是用户自己打或说的（粘贴不经过输入法），是记忆里最直接的一类"用户本人说的话"。
- 计划：重排打分和联想的评测集（给主控的配方，见"对主控的需求"）。

## 对主控的需求

**身份**：对主控来说配件只有一个，"luoke-ime"（配件清单 `luoke-accessory.json` 在 LuokeIME.app 的 Contents/Resources，`type` 是 `input-method`，`memory` 为 true；`data` 是 `["~/.luoke/ime"]`：卸载时主控删 `~/Library/Input Methods/LuokeIME.app` 和这个目录，里面只有输入法自己的设置、各引擎的数据、开发模式的记录和用户装的引擎，不含 `mem.db`；另有系统临时目录里的 `luoke-ime/`，空的，删不删都行；2026-10-16 和 luoke-core 对过）。只有壳（Swift，不在沙盒里）连主控的 socket；输入法引擎和个人化组件的请求由壳转发，壳只看声明、不看内容。

**任务**（草案，名字和数值待主控定）：

| 任务 | 方式 | 用在哪 | 延迟要求（草案） | 任务参数 |
|---|---|---|---|---|
| 重排打分 | 打分，专用模型 | 打字时按前文逐词选首选 | 单次打分 p90 不超过本机阈值：主控实测（底座未加载）基础款 M4 63 ms、M1 16 GB 124 ms；最后一个键之后整次重排约 150 ms 内到（按空格时壳最多再等 150 ms），基础款 M4 上输入法独占时 p90 186 ms | 门槛 τ（nats，现在是 3） |
| 联想 | 续写（通用原语，2026-10-16 起：前文后面最可能的 k 个开头各贪心续几个 token，交回逐个 token 的文字和对数概率；停止串由输入法传，怎么截、挑哪几个、门槛都在输入法，草案见 `luoke-ime/docs/续写接口草案.md`，待 luoke-core 定稿进 V1 §2） | 上屏后给接着写的候选 | 上屏后约 300 ms 内备好（在用户按 Tab 之前）；壳等 1 秒 | 每个开头续几个字、把握门槛（现在 8 个开头、6 个 token、平均每字对数概率 ≥ −2.5） |
| 语音识别 | 以后 | 语音输入 | 待定 | 待定 |

- **慢的机器**（主人 2026-10-13 定）：主控在 `GET /tasks` 里给 `luoke-ime.rerank` 标了 `slow`（按实测，不按内存档位；2026-10-14 起主控用固定形状的探针测，各档同一个阈值 50 ms、低于 40 ms 才清，和输入法给多少候选无关：M5 Max 13.9–17.6 ms 不慢，基础款 M4 59 ms、M1 135 ms 慢），输入法就每一步少给模型一半候选（个人化组件随打分答复告诉引擎）。M1 16 GB 上逐键重排 p90 约 500 ms，经主控和本机一样，是机器能力（luoke-core `docs/experiments/coexistence-e2e.md`）；减半的代价是首选 89.8% → 88.8%（M5 Max、M1 一样）；M1 16 GB 上经主控（luoke-core 实测，coexistence-e2e §5）最后一个键到选好 p50 / p90 364 / 539 → 260 / 364 ms，停顿 200 ms 后按空格时上屏的首选 82.0% → 87.0%，不停顿 70.5% → 80.3%。再减候选收益很小（每次打分固定部分占大头），所以慢的机器上一次重排还限 2 步（第 2 步整句一起定，停下来后再不限步数选一遍），模型算着时先答新键的快候选：M1 16 GB 上经主控实测（luoke-core coexistence-e2e §6）：第一份答复 p90 104 → 32 ms，选好 p50 / p90 260 / 364 → 150 / 183 ms，停顿 0 / 100 / 200 ms 按空格的上屏首选 80.3 / 82.5 / 87.0% → 83.5 / 88.0 / 88.2%（engines/xiaohe/README.md）。
- **打分的用法**：一次请求 10–15 个候选，共享前文；同一句里"前文 + 已定的词"反复出现，需要前缀缓存（主控已接，2026-10-11：按配件保留最近几条前文的 KV 快照，条数是任务参数，初值用我们现在的 16 条）；用户敲了下一个键就取消（关连接）。
- **不可用时**：主控不可用、或打分返回 `not_ready`，输入照常（苹果和 RIME 的候选），只是没有重排和联想；发布版不退回本机打分（主人 2026-10-14 定）。输入法的主要功能不依赖 AI，这两个都是可选任务。
- **第三方引擎**（luokelabs/luoke-ime#6，主人 2026-10-16 定，输入法 ADR 0012）：装在 `~/.luoke/ime/engines` 里的引擎不能联网、不能用 GPU、只能写自己的数据目录，要用模型只经主控的任务（输入法自己的 `luoke-ime.rerank`、`luoke-ime.predict`）；用户确认了才启用。没允许保存到本机记忆时，上屏不转给任何个人化组件。
- **门槛和测速探针归输入法**（V1 §10b，2026-10-16）：重排"有把握才改"的门槛在引擎里（小鹤、全拼的选项 `gate`，默认 3 nats），配方里不再有 `threshold_nats`。主控测打分延迟用的前文和候选由输入法定，照真实请求的形状（重排：前文约 50 字、10 个候选；联想：前文约 36 字，走 `/v1/continue`，k 8、max_tokens 6、输入法的 34 个标点作停止串），写在 luoke-core 配方的 `params.*.probe` 里；输入法的请求形状变了要告诉 luoke-core 改那一块。
- **和后台共存**（主控实测 0，`luoke-core/docs/experiments/coexistence.md` §9–§10）：底座在内存里时，基础款 M4 上最后一个键到重排结果 p90 从 186 ms 涨到 936 ms，后台 prefill 时 1.8–2.6 s，打断要 6–11 s，救不了打字。让路的做法由主控定（V1 §3：最近几分钟有打分就不接后台请求、后台请求按硬件档限长、16 GB 档只在安静时刻加载底座做后台）。输入法这边不需要改：重排慢了，按空格时就用快的那份候选。主控上线前不另做协调；要过渡措施的话归 luoke-mail（它的"静音"功耗档或把整理排到夜里），M5 Max 这类机器上可能根本感觉不到。
- **系统要求**（主人 2026-10-15 定）：输入法 macOS 26 起（只在 26、27 上验证过：靠的苹果私有转换引擎在更早的系统上可能不同，添加输入源的规则也不同）；主控首次运行时 26 以下不装输入法、说明原因，邮件助手照旧。LuokeIME.app 自己的最低版本暂留 14，封闭测试里招 2–3 位 14、15 的测试者手动装上验证，过了再放宽。
- **安装和启动**：装在 `~/Library/Input Methods/LuokeIME.app`，bundle id `ai.luoke.inputmethod.Luoke`；第一次装好后要用户在系统设置里手动添加输入源（macOS 26 起）；由系统的输入源机制拉起，不是常驻配件，不调用 `PUT /accessory/resident`；正常退出（收到 SIGTERM 等）前调 `POST /accessory/exiting`（0.1.7 起，luokelabs/luoke-ime#9），被强制结束时调不到，打分进程空闲停由主控做（luokelabs/luoke-core#11）。只当一份输入法服务：不是 launchd 拉起的、或已有一份在跑就退出。主控的安装流程要能装到这个位置，并引导用户添加。用户绕开主控、自己打开 LuokeIME.app 而螺壳还没被添加时，输入法自己弹添加的引导窗口（0.1.9 起，文字和主控的完成页一致）；带参数运行时不弹。查用户添加了没有用 `LuokeIME --status`（0.1.9 起，一行 JSON，`state`：`not_registered` / `not_added` / `added_not_selectable` / `ready`；luokelabs/luoke-ime#13）。0.1.11 起 `--status` 多了 `other_copies`（同 bundle id 的别的副本，含废纸篓里的；不空多半切不过去），`--select` 会核对真的切过去了（退出码 0 切过去了、1 调用失败、3 调用成功但没切过去）；0.1.21 起 `--select` 发现输入法服务没在跑会先拉起它，刚添加完时在主控自己的窗口里切过去就能打（主控那边另外在 `--status` 第一次答 ready 时预先拉起、让试打框重新聚焦，和 luoke-core 10-27 商定），安装前要先注销别的副本（luokelabs/luoke-ime#15）。**换版**：旧进程找资源、起引擎都按包的路径，换包后不能留着跑旧代码。主控换好包以后结束跑在换下来那份里的进程（SIGTERM，3 秒后 SIGKILL），再 `open -g` 装好的路径（luoke-core d1d7ef6）。输入法 0.1.18 起自己也兜一层：发现磁盘上包里的 build 号和启动时不同，就等没在打字（所有输入框空闲、3 秒没按键）时自己退出，再 `open -g` 拉起新版，最多晚 5 秒左右。
- **发布时怎么带引擎**（主人 2026-10-14 定，`luoke-ime/docs/发布打包.md`）：自带的小鹤、全拼、个人化组件放进 LuokeIME.app（`Contents/Resources/engines/`），和壳一起签名公证；主控照旧只装 LuokeIME.app，发布清单不多一项。已做：58 MB，公证通过。
- **借主控的 Python**（luoke-core 已接，写进它的注册页和 V1 §8）：个人化组件（只用标准库）用主控包里的 `螺壳.app/Contents/Resources/python/bin/python3`（internal-1024-2 以前叫 螺壳主控.app，两个名字都认，0.1.14 起；先找 /Applications 再找 ~/Applications，0.1.19 起）（V1 §8 写明的布局）。壳按 bundle id `ai.luoke.core` 找主控、在沙盒里起这个 Python（`PYTHONDONTWRITEBYTECODE=1`，只读）；找不到主控就没有个人化组件，打字照常。要主控保证：这个路径和 bundle id 不变；Python 3.9 以上、带 sqlite3 的标准库；同一个 Team 签名、hardened runtime；主控升级换 Python 时提前说。
- **读写记忆**：按接入契约（luoke-core DESIGN §11 组件配件），输入法在给主控的配件清单里声明"读写记忆"，主控装输入法时把螺壳记忆一起装上。读写记忆的是沙盒里的个人化组件，它用主控 Python 里带的那份 luoke_mem（`螺壳.app/Contents/Resources/python/lib/python3.12/site-packages`，2026-10-19 和 luoke-mem 商定），输入法不自带；主控换了 Python 或 luoke_mem，壳会重启个人化组件。
- **最敏感**：它看得到用户打的每一个字，"请求文字只在内存里、不进日志"对它最要紧。
- **评测集**：重排打分用小鹤引擎的 `bench.py`（经引擎协议逐键回放，报首选准确率和延迟；主控的发布脚本已接，读标准输出），联想用 `engines/personal/eval_predict.py --hub <socket>`（经主控的 `luoke-ime.predict`，看前文后面真正接的那句是不是以联想开头）。两个都有 `--result FILE`，照 V1 的证据格式写 JSON（配件版本和提交号、评测集哈希、模型和任务参数、机器和芯片、日期、汇总、逐条对错和用时，不带语料原文），发布脚本可以改读它（2026-10-13）。现有语料是私有的博客语料，只在实验室的机器上跑：配方里只记结论和证据哈希、不带语料（和 luoke-core 商定，2026-10-11）。要让社区测试者复现时才需要公开语料，另定。
- **错误码**：个人化组件现在给引擎的 `score` 错误码（`not_ready`、`unavailable`、`timeout`、`expired`）是自己定的，接主控时对上主控的原因码和 `retry_after`。

## 在记忆里读写什么

由输入法里的**个人化组件**读写（Python，用 luoke_mem 库；工具标识 `luoke-ime`）。它在 Seatbelt 沙盒里、不能联网；声明了 `memory` 权限后，沙盒只放行记忆文件本身和 SQLite 的 `-wal` `-shm` `-journal`（不跟随符号链接），路径由壳经环境变量 `LUOKE_IME_MEMORY` 给（默认 `~/.luoke/mem.db`），`~/.luoke` 下别的东西照样读不到、目录本身也改不了。

**写的记录**（已做；话题和写法和 luoke-mem 商定）：

| 话题 | 谁说的 / 性质 | 一条是什么 |
|---|---|---|
| `ime-commit` | 用户 / 陈述 | 上屏的文字，同一应用里接连的上屏合成一段记一条；这一段开始时光标前的字放在 `data.context`、标成第三方写的（2026-10-19 起，顶层 ADR 0013；记忆只拿它理解上下文）；原来只放上屏的字、不放前文（前文可能是别人写的）。`data` 第一层放 `app`、`source`（哪个输入法引擎）、`kind`（打字、标点、语音）、`auto`（切走时自动上屏的，归纳时不当依据） |
| `ime-correction` | 用户 / 活动 | 上屏后马上删改、在候选里改选；跟着所在的那一段写，那一段敏感就一起不记 |
| `ime-forget` | 用户 / 陈述 | 忘掉候选（候选窗里 Shift+⌫）；候选来自一条 `term` 时对它调 `reject`（不调库的 `forget`：那是从记忆里忘掉，真删除） |
| （以后）导入的资料 | 用户或第三方 / 陈述 | 由通用的导入入口写，输入法只读 |

**写的理解**：没有。常用的说法和专名（`term`）、从打字里看出的关注话题，由 luoke-mem 从输入法写的记录里归纳（顶层 ADR 0005，主人 2026-10-14 定），多次一致、敏感的上下文只认用户本人确认的，由它把关。输入法只写记录；记录里要补哪些字段，等 luoke-mem 来对。

**怎么写**：组件用主控带的那份 luoke_mem（跑在主控的 Python 上，luoke-mem 2026-10-19 定），不自带；在后台线程里写，别的工具正写时最多等锁 10 秒，不能让转问的答复等它。上屏原文默认一直保留；用户设了保留期，组件才定期调 `forget_records(..., until=..., keep_cited=True)`。

**读的理解**：关于你、关注的话题、常用的说法：给模型当前文的一部分，给候选加分，给语音当热词，给联想当素材。

**记忆记录**：自带的个人化组件默认开（顶层 ADR 0013，主人 2026-10-19 定），第一次切到螺壳时提示一句，全局设置里能关（"记录输入内容到本机记忆"）；2026-10-19 以前问过没开的照旧关着。关着时沙盒不放行 `mem.db`、上屏不转，组件照样打分、联想。第三方的个人化组件要用户另外打开。

**不记**：密码框等安全输入时什么都不记（安全）；设了"禁止记录"的应用、用户暂停所有记录时上屏不转（用户自己的开关），打字引擎也收不到反馈。凭证只遮那一串、其余照记（`mask_secrets`，顶层 ADR 0013）；健康、法律、宗教政治照 `sensitive_kinds` 标上类别、不藏。规则在输入法的 `PersonalPolicy` 一张表里。

## 和记忆商定的

2026-10-10 和 luoke-mem 的会话商定，上面"在记忆里读写什么"已按它改；对方的答复见 `luoke-mem.md`「和使用方定下的」。

- 我们提的"在沙盒里能打开"：luoke-mem 0.4 已改（权限对时不再 chmod，改不了目录时照常打开）。
- 对方提的"壳第一次建 `~/.luoke` 时用 700"：已做；壳自己的 `~/.luoke/ime`（有开发模式的按键记录）也收紧到 700，已有的松权限在启动和安装时收紧。
- 主人已定：上屏原文默认一直保留，用户可以在输入法里设保留期（2026-10-10）。
- 记忆文件比库新时打开抛 `luoke_mem.TooNew`，输入法在菜单里标"记忆打不开"。原来的敏感三类、原始记录只读自己写的（旧顶层 ADR 0002、0004）2026-10-19 起由顶层 ADR 0013 取代，见上面"不记"。
- 输入法自己的界面（计划）：只显示输入法写的理解（常用说法等），可以否定、修改、从记忆里忘掉单条，并链到 luoke-mem 的界面；按来源删、清空全部只在 luoke-mem 的界面里做。
- 整份记忆的入口（顶层 ADR 0003，已做；2026-10-16 改成 `luoke://memory`）：输入法菜单里的"管理记忆…"和设置窗口的"查看和管理记忆…"，`mem.db` 存在时才显示，`open luoke://memory` 打开（记忆 beta1 起并进主控，luoke-core 注册页「记忆并进主控、luoke://memory」）；系统里没有认领 luoke:// 的应用时退回旧的「螺壳记忆.app」（bundle id `ai.luoke.memory`，过渡期用），都没有时显示成灰的"还没装螺壳"。壳不派生进程、不带 luoke_mem、不起 Python，也不用 `-m luoke_mem` 这样的命令行起任何东西（主控按它认记忆进程）。卸载输入法时的"一起从记忆里忘掉"由主控跑 `forget-tool`。

## 现状数据

- 博客语料 600 条首选准确率：苹果 78.8%，重排后约 90%（小鹤、全拼都是）。
- 120 ms 一个键的逐键打字，最后一个键到重排结果：M4 中位数 122 ms、p90 186 ms；M5 Max 中位数 57 ms、p90 76 ms，模型搬进个人化组件后 60 / 77 ms（准确率逐条不变）。停顿 100 ms 按空格，上屏首选准确率 90.5%。
- 联想（博客语料，只测模型那一路）：模型对下一个词的把握 ≥ 0.2 才给，约 7% 的上屏有联想，给出时第一个就对 41%、前三个有对 49%；每次 18–24 ms（M5 Max）。
- 本机统计（模型在真实输入里帮了多少）记在输入法引擎的数据目录 `stats.json`，只有次数。
