# 螺壳官网和社区 luoke-community

- 仓库：[`luoke-community/`](../luoke-community)。方案：`docs/封闭测试.md`、`docs/官网.md`、`docs/社区运营.md`；进度：`STATUS.md`
- 本页由 luoke-community 维护。

## 是什么

螺壳实验室（Luoke Labs）的封闭测试、官网和用户社区「螺壳社区」（顶层 ADR 0017）。

- **封闭测试**：招募测试者、按覆盖表（内存档、芯片、邮箱、输入法）挑人、分两批开始、给测试说明、收反馈、按组件转给各项目、结束时汇总。
- **官网**：前端在本仓库 `site/`（Astro 静态站）。改动先在 luoke-brand 的 `site/` 做，确认后同步过来；本项目负责页面上的事实和出处。
- **社区**：公开以后的渠道、节奏、内容（实验笔记、发布说明、月报）。平台上的图文和视频由内容工作区做，本项目给事实和出处。

## 对外提供

- **封闭测试的材料**（`beta/`）：测试说明、连接邮箱、已知问题、招募帖和报名问卷、周问卷和结束问卷、GitHub 反馈表单（装机报告、问题、卡住了、建议、邮件分错了）。测试说明、已知问题和表单发布在封闭测试仓库，用 `beta/publish.sh` 同步。
- **反馈分拣**：封闭测试期间每天看新问题，打组件标签（安装和首次运行、邮件助手、输入法、记忆、主控）和严重程度（阻断、严重、一般），合并重复的，转给对应项目；功能建议打"公开后"标签。各项目可以用 `gh issue list -l <组件>` 读自己那部分。
- **问卷结果**：只带测试编号，放在 `beta/结果/`。
- **官网**（`site/`）：各档体验、系统要求、实测数字只存一份、带出处（`site/data/tiers.json`、`claims.json`）。
- **应用图标**：`icons/brand-a/` 里是品牌 A 版打好的 `.icns`（主控 / 安装器、邮件助手、输入法）。

## 依赖

| 依赖 | 用来做什么 |
|---|---|
| luoke-core | 系统要求、各档体验、安装、升级、卸载、诊断信息的说法；测试版的下载地址 |
| luoke-mail | 邮件助手那页、授权码引导、"分错了"怎么报、问卷题、已知问题（`luoke-mail/docs/community/`） |
| luoke-ime | 输入法那页、添加输入源、写引擎入门、问卷题、覆盖要求（`luoke-ime/docs/首发/`） |
| luoke-mem | 记忆那页、头几天看到什么、问卷题、截图（`luoke-mem/docs/community/`） |
| luoke-agent | agent「螺壳」（开发中）那页 |
| luoke-brand | 官网前端、logo、应用图标、吉祥物、介绍文案（`media-kit/`） |

## 对别的项目的需求

**对 luoke-core**：每个测试版（beta1、beta2……）出版后给下载地址，测试说明照它填。

**对所有首发项目**（luoke-core、luoke-mail、luoke-ime、luoke-mem），封闭测试期间：

1. 新的已知问题告诉本项目，本项目更新 `已知问题.md`。
2. 修好的问题在对应 issue 里写明哪个版本修的。
3. 素材里的数字或说法变了告诉本项目，测试说明和官网跟着改。

**对 luoke-agent**：公开发布前给"开发中"那页的素材；社区什么时候能写工具，定了告诉本项目。

## 在记忆里读写什么

不读不写。官网和社区的素材不用真实用户的数据，截图用示例收件箱和示例记忆。

## 要守的底线

- 对外的事（发帖、邀请测试者、官网上线）每件先确认再做。
- 测试者的名字和联系方式不进仓库，只放编号和覆盖表；问卷结果只带编号。
- 反馈不要用户的内容（不贴邮件原文、打的字、记忆的内容）；诊断只含元数据，由用户决定发不发（顶层 ADR 0013）。
- 官网不放跟踪代码、第三方字体和脚本。
- 每个数字有出处，各档照实写。
