# 螺壳邮件助手 luoke-mail

- 仓库：[`luoke-mail/`](../luoke-mail)；设计：`luoke-mail/docs/DESIGN.md`；现状和已知问题：`luoke-mail/CLAUDE.md`
- 本页由 luoke-mail 的会话维护。

## 是什么

用本机模型整理整个邮箱：
- 近期邮件逐封分拣，一键处理；
- 收件箱里的旧邮件和已归档的邮件，在「清理」里逐封判断；
- 订阅体检和退订；
- 订阅精选：替用户读订阅，最近一周挑约 20 条、更早的每月约 10 条；
- 起草回复，只放进草稿箱；
- 「今日处理」：每天处理过的每一封和它的结果，逐封撤销或修改。

支持 Gmail、QQ、网易 163/126 和自定义 IMAP，可以同时连接多个邮箱。形态是只监听 127.0.0.1 的本机网页，打包成签名公证的「螺壳邮件助手.app」（`ai.luoke.mail`），由主控在登录时拉起、保活。

**替用户做事的边界**（顶层 ADR 0016）：
- 能撤回的先做、事后复查：分析过的邮件标为已读；记忆里确认过的习惯（按「发件人 × 类别」）自动归档、标已读或加标签。每封都列在「今日处理」里，能撤销，撤销记成反证。
- 用户自己的邮箱里，移到垃圾箱、标垃圾邮件、退订永远要用户点；批量的这类操作要先开「处理模式」。
- 螺壳自己的邮箱（第 5 条）：用户另开、专门给螺壳、在设置里明确设为「螺壳自己的邮箱」的那个邮箱，里面的归档、移到垃圾箱自动做，同样进「今日处理」。
- 永远不发信、不永久删除、不转发。

## 对外提供

- **写进记忆的记录**，以及读理解的方式：见下一节。
- **用户的网站和博客**：用户在记忆页填写网址，存成「关于你」的一条（`topic=site`），其他工具也能读到；读到的文章记成 `own-site` 记录。
- **空闲任务**（清单 `jobs`，由主控在安静时刻起进程跑）：`clean`（分拣范围以前的未读邮件，每个邮箱只排一次；判断清理里的旧邮件）、`digest`（读订阅、挑精选）、`learn`（了解你，整理用户自己的资料和阅读记录）。被叫停就停在做完的那一步、退出码 0，下次接着做。
- **卸载**：清单 `data: ["~/.luoke-mail"]`、`commands.uninstall: ["-m", "luoke_mail", "--forget-secrets"]`（删钥匙串里本工具的授权码），只在用户勾了「同时删除我的数据」时由主控运行。
- **给 agent 的接口**（luoke-agent 工具协议）：数据目录 `run/agent.sock` 上的 MCP 子集——outbox（要处理的新邮件、可疑邮件）、按用户点按执行方案、撤销、打开页面和日历。v1 首发版关掉（`LUOKE_MAIL_AGENT=1` 才开，清单不声明能力），螺壳发布时打开。已和 luoke-agent 商定、待实现的：`auto-done`（按习惯自动做了什么，合成一件、按习惯分组、每组 `mail.undo {log_id}`）和 `daily-review`（每天的「今日处理」，urgency low，带 expires）。

## 在记忆里读写什么

**工具记录，记忆下结论**（顶层 ADR 0015）：邮件助手把发生了什么写成记录，带原文；关于用户的事实、关注的话题、不感兴趣、精选的口味、处理习惯都由 luoke-mem 归纳和定档，问什么也由它定。工具标识 `luoke-mail`。示例收件箱用单独的记忆文件。

**每条记录都带**：`account`（来源邮箱）、`sender`（`list:` / `from:`）、`name`、`by`（user / rule / suggestion）、`happened_at`（真正发生的时间）。凭证经 `mask_secrets` 只遮那一串，其余原样（ADR 0013）；敏感的上下文用 `sensitive=` 标给记忆。

**写的记录**

| 话题 | 谁 / 性质 | 内容 |
|---|---|---|
| `sent-mail` | 用户 / 陈述 | 发出的邮件里的一件事（ref `<Message-ID>#<话题>`，`data.text` 是用户在那封里写的部分）；用户发起的邮件主题 |
| `received-mail` | 第三方 / 陈述 | 一个机构多次来信（封数、跨几个月、打开几封、最近一封） |
| `mail-read` | 用户 / 活动 | 每个订阅每月一条：收到几封、用户打开几封（邮件助手标的已读不算）、`category`；`mails` 是这个月打开过的最新三封原文 {subject, date, text}，事务邮件不带 |
| `mail-acted` | 用户 / 活动 | 用户亲手的处理：`action`（archive / trash / spam / read / label）、`label`、`category`、`count`、`where`（here：在邮件助手里；elsewhere：在 Gmail 网页或手机上，同步时发现） |
| `mail-override` | 用户 / 陈述 | 用户改过的一条建议（`from`、`to`、`category`） |
| `mail-auto` | 规则 / 活动 | 按确认过的习惯自动做的（`note_id`、`action`、`label`、`category`） |
| `mail-undo-auto` | 用户 / 活动 | 用户撤销了一次按习惯做的：反证 |
| `own-site`、`own-label` | 用户 / 陈述 | 网站上的文章（feed 的发布时间）、用户自己建的邮箱标签（时间是标签下最新一封） |
| `digest-feedback`、`digest-open` | 用户 / 陈述、活动 | 精选里的收藏、没兴趣、打开（`source`、`text` 是那一条的标题和摘要） |
| `mail-cleared` | 用户 / 活动或回执 | 整批移到垃圾箱的一个发件人（类别、封数、`by`） |

**交给记忆的事实**：发出的邮件里两封一致的 `conclude`；机构来信抽出的事实 `propose`，由记忆按证据定档。

**读的理解**：
- 分拣和起草回复用 `fact` + `preference`；
- 精选用 `taste` + `interest` + `dislike`；
- 确认过的习惯（`auto`，`archive` / `read` / `label`，必须带 `category`）由邮件助手照做；
- 记忆页显示全部类别，依据给全文；「想问你的」读 `asks(tool="luoke-mail")`，答复交给 `reply`。

**记忆归用户**：记忆页能否定、修改、删除单条，底部「忘掉邮件助手记下的内容…」调 `forget_tool()`；用户在邮件助手页面上说的话归记忆，不随它忘掉；不调 `forget_all()`，也不对别的工具调 `forget_tool()`。

## 依赖

| 依赖 | 用来做什么 | 怎么用 |
|---|---|---|
| 主控 luoke-core | 本机模型 | .app 只走主控的任务层：调用写任务名和条目数，字符上限和批大小从 `GET /tasks` 读，按 `retry_after` 等；源码运行也可直连 OpenAI 兼容的服务（开发用） |
| 记忆 luoke-mem | 读写记录和理解 | .app 先用主控 `GET /tasks` 报的 `luoke_mem.path`，没有再用自带的兜底那份；要求 0.23 或更新；数据在 `~/.luoke/mem.db`，归用户 |
| 邮箱 | 读写邮件 | IMAP + 应用专用密码 / 授权码，存在 macOS 钥匙串（`luoke-mail:imap`，每个邮箱一条）；不需要任何云端授权 |
| macOS | 常驻、通知 | 由主控在登录时拉起、保活（`PUT /accessory/resident`），通知经 .app 的启动器 |

## 对主控的需求：任务

任务参数是建议值，由主控写进配方；luoke-mail 只从 `GET /tasks` 读。都不思考，都要求按 JSON schema 输出；输出不合格式时再问一次。

| 任务名 | 做什么 | 请求等级 | 一个条目 | 每条目预算 + 固定开销（token） | 批大小 |
|---|---|---|---|---|---|
| `luoke-mail.triage` | 分拣 | 用户看着时「用户在等」，否则后台 | 一封邮件 | 320 + 80 | 1 |
| `luoke-mail.draft` | 起草回复 | 用户在等 | 一封邮件 | 800 + 100 | 1 |
| `luoke-mail.senders` | 订阅体检的发件人判断 | 用户在等 | 一个发件人 | 25 + 60 | 10 |
| `luoke-mail.cleanup` | 清理判断 | 后台 | 一封邮件头 | 30 + 60 | 25 |
| `luoke-mail.digest-read` | 订阅阅读 | 后台 | 一封订阅（正文按字符上限截短，输出最多 8 条） | 1300 + 100 | 1 |
| `luoke-mail.digest-pick` | 精选挑选 | 后台 | 挑中的一条（最多 30 条候选） | 60 + 60 | 30 |
| `luoke-mail.learn-sent` | 了解你：发出的邮件 | 后台 | 一封发出的邮件 | 100 + 100 | 8 |
| `luoke-mail.learn-orgs` | 了解你：机构来信 | 后台 | 一个机构 | 60 + 100 | 10 |
| `luoke-mail.thread` | 往来邮件卡在谁那里（等对方 / 等你） | 后台 | 一串往来（最后 6 封） | 60 + 100 | 1 |

**评测集**（硬性条目全过才开，各档开不开由主控按评测定）：
- 分拣：`bench/`，47 封（19 封难题，含钓鱼、注入、发件域名验证）；硬性条目是正常邮件 0 误报、可疑邮件最多漏 1 封。
- 其余任务：`bench/task_sets.py` + `bench/run_tasks.py`（应用自己的代码路径，直连或经写明的主控，结果带题集 sha256）——清理判断、订阅体检、了解你（发出的邮件、机构来信）、`thread`（硬性条目 `done_as_you`、`missed_you`）。
- 起草回复、精选的阅读和挑选还没有评测集。

## 对主控的需求：日历（beta1 之后，ADR 0014 修订）

邮件助手要用主控的本机日历接口，判断「这封邮件的日程是不是已在日历里」（luokelabs/luoke-ops#3），具体怎么做和 luoke-core 商定：
- 按时间段读事件：标题、开始和结束时间、地点、所在日历、事件编号。
- 写一个事件，返回事件编号；写到用户选定的默认日历（第一次加日程时选一次）。
- 按编号改一个事件的时间，或者删掉它：同一个预约改期时，把原来那条换到新时间。
- 邮件助手把事件编号和那封邮件一起记下，这件事邮件助手自己做。

## 对记忆的需求

- 已落实：`mask_secrets`、全文依据、习惯按（sender、category、action、label）归纳并标 `auto`、`redate`、`asks` / `reply`、读原文归纳话题（`luoke-mem.topics`）、整份记忆的页面 `luoke://memory`。
- 现在没有未落实的需求。
