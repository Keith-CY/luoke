# 替用户做事：能撤回的确认后自动做并提示，不可逆的永远要用户点

2026-10-19，主人决定（取自归档的 0006 和 0012 修订）。

## 决定

1. **能撤回、不毁灭的，用户确认一次之后可以自动做**，比如归档、标已读、加标签、给出 filter 建议。
   - 每次都要提示用户做了什么，并且能撤销。
   - 用户撤销一次，就算这条习惯的反证。
2. **不可逆或对外的，永远要用户自己点**：删除（移进垃圾箱）、标垃圾邮件、退订、发信、花钱、往外传数据。
3. **习惯的来路**：
   - 记忆从用户亲手做的处理里归纳习惯，按"来源 × 类别"记，比如"某商城的促销邮件"。在哪里做的都算，在 Gmail 网页或手机上做的也算。改过工具的建议也算。
   - 归纳出来以后，出一条建议"以后这类都这样？"，不看隔了几天；用户点"好"，这条习惯就是确定。
   - 工具按规则自动做的，记成"规则做的"，不拿来加固同一条习惯。
4. **先做、事后复查**（主人 10-19）："AI 处理过的应该就是已读了，然后根据学习的结论该归档归档，事后我自己 review AI 的处理是不是对"。
   - 邮件助手分拣过的邮件标成已读；
   - 有确定习惯的照习惯归档；
   - 每天给一个复查页，列出今天处理过的全部邮件和各自的处理（没自动处理、留在收件箱也算一种结果），用户在那里一键撤销或改；
   - 改了就是反馈。要用户处理的（回复、日程、可疑）照旧提醒。
5. **AI 自己的邮箱**（主人 10-19 定）：推荐用户给螺壳开一个独立邮箱，把相关的邮件转过去（邮件助手一键生成转发规则）。
   - AI 自己的邮箱里，读、归档、删全自动。
   - 从 AI 的邮箱往外发信，默认先存草稿等用户点。用户可以按类型放开，比如退订、回复确认、预约改期这类低风险的；放开以后它直接发，每封都进每日复查页。
   - 以用户的名义、从用户自己的邮箱发信，永远要用户点。
   - 外发跟 agent 一起出（v1.x）。beta1 先做邮件助手里"推荐给螺壳一个自己的邮箱"的引导和一键转发规则。
6. **内测别太保守。** 可撤回的能力默认放进测试版，配上提示和撤销，看真实反应；反对的声音多了再调。

## 为什么

主人原话："自动整理里进行归档，或者给用户一个 filter 建议，都属于可撤销的不会造成毁灭性影响的，这个是可以接受的，如果反对的声音多我们再调整""之所以要做内测，就是为了看到用户真实反应，而不是先假设用户不接受自缚手脚"。

## 修订（2026-10-20）

- **会重建的缓存可以确认一次后自动清**：系统检查（luoke-audit）查出的"会重建的缓存"（npm、uv、pip、cargo、go、bun、swiftpm、Xcode DerivedData、Homebrew 旧版本这类，删了由工具自己重建、不丢用户数据），用户确认一次后可以对这一类自动清，每次清完提示；对应应用正在使用时跳过，优先用工具自带的清理命令。其余类别（卸载残留、久未动的项目、重复文件、用户文件等）每次都要用户点，删除优先移到废纸篓。"删除不自动"对用户的邮件和文件照旧。
- **只往本机下载的规则和特征库不算数据外传**：病毒特征库、规则包这类签名过的文件，从上游或团队的分发下载到本机，不上传任何东西，符合 ADR 0013；下载频率守上游的规矩。
