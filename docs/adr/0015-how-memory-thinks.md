# 记忆怎么想：工具记下发生了什么，记忆读原文、下结论、先粗后细

2026-10-19，主人决定（把归档的 0005、0009、0010、0012 里仍然有效的合在一起；去掉"邮件正文不进记忆""只靠工具喂的摘要"这类限制）。

## 决定

1. **工具只记发生了什么，不下结论。**
   - 要记的包括：用户做了什么、收到了什么、工具按规则做了什么，每条标明是谁做的（用户、第三方、规则）、什么时候真正发生。
   - 记录里可以带原文：邮件主题和正文、打的字等。
2. **记忆读原文去理解。** 归纳时，记忆读这些原文，必要时向工具要更多，弄清楚到底在讲什么。比如"Zillow 的邮件"要理解成"关注某个邮编的美国房价"，不能只照来源名字起话题。标准是：像一个用心的个人助理那样。
3. **三档把握程度：猜测 / 比较确定 / 确定。**
   - 各工具只用比较确定以上的。
   - 确定只来自用户说的或确认的。
   - 什么记录能推出什么、要多少证据，由记忆在自己的 DESIGN 里定，不进顶层。
4. **先粗后细，按反馈逼近。**
   - 不让用户事先定规则、审预览、逐条点头。
   - 先给合理的默认，直接用；用户的确认、否定、撤回、"别再提"就是调整的信号；门槛按每个用户各自调整。
5. **看时间。**
   - 每条理解按依据里最新一条的真实时间算新鲜度。
   - 会变的（工作、城市、兴趣、在用的服务、习惯）太久没有新依据，就算"以前的事"：留着、标上年份，不当成现在的事用，也不当成现在的事问。
   - 不会变的（姓名、"曾就读"）不受影响。
6. **反刍：记忆在空闲时整理，产出"想问的"和"建议"。**
   - 只问用户才能定的、答了有用的；邮件里看得出的事实不问。
   - 测试期上限：每天想问的最多 2 个、建议最多 3 条。公开前给用户自己调节的地方。
   - 记忆只提议，不动手。
7. **用户对理解说的话归记忆**，注明是经哪个工具说的。卸载某个工具时，用户确认过、否定过的留着。
8. **不按"上下文"隔离记忆。** 用到记忆时哪些相关，由用记忆的工具和 agent 在编排和提示词里判断。工具在记录里标来源（比如哪个邮箱），给编排当信号。

## 为什么

试用期的教训：邮件助手和记忆各自推测、互相打架；只看"是不是用户的"就直接生效，于是建了个标签就被推成"不感兴趣"；记忆只拿到发件人名字，归纳出来的都是"X 相关动态"；十年前的信息被当成现在来问。主人："最好能按照'先粗后细，根据用户反馈'的原则来设计，渐进式逼近每个用户自己的偏好"。
