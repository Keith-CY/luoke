# 分工：模型在主控，理解在记忆，事情在工具，沟通在 agent

2026-10-19，主人决定（把归档的 0001、0003、0005、0006 里仍然有效的分工合在一起，去掉其中的隐私限制）。

## 决定

| 谁 | 管什么 |
|---|---|
| **主控** luoke-core | 本机所有模型的加载、显存、功耗、排队；工具按"任务"要结果，不点名模型。提示词、输出格式、语言上的判断写在调用它的工具里，主控只提供通用的推理原语。主控也是安装器：装、升级、卸载各配件，并调度各配件登记的空闲任务（只管什么时候跑）。|
| **记忆** luoke-mem | 一份 `~/.luoke/mem.db`，归用户，不归任何一个工具。它保存各工具记下的"发生了什么"，并且是**唯一下结论的地方**：关于用户的理解（事实、关注的话题、不感兴趣、处理习惯、常用说法）全由它归纳，见 ADR 0015。代码归 luoke-mem；界面和归纳从主控 .app 里跑，打开方式是 `luoke://memory`。|
| **工具**（邮件助手、输入法……）| 把自己那件事做好，把发生了什么写成记录，读记忆的理解来做事；用户确认过的习惯由工具执行，见 ADR 0016。|
| **agent** luoke-agent（给用户看的名字叫「螺壳」）| 唯一主动找用户的出口：把记忆想问的、建议的，以及各工具的提议，合并起来、挑时机说；代表用户调用各工具声明的能力。|

- **工具之间不互相调用**：调用工具声明能力的只有 agent。工具之间读彼此的数据不受限，见 ADR 0013。
- **每个工具一个签名的 .app**；一个工具内部可以有自己的组件和进程。
- **空闲任务**：任何配件都能在清单里登记"空闲时跑"的命令。主控只决定时机（有空闲算力、用户不在、电量和内存允许），用户回来时让它收尾。
- **首发组件公开前冻结能力**：封闭测试期间，首发组件只修问题、不加给 agent 的新能力（见 ADR 0017）。

## 为什么

- 显存、功耗、排队只能有一处管，所以模型归主控。
- 只有记忆看得到所有工具的记录，下结论放在一处，规矩也只用实现一次。邮件助手和记忆各自推测、互相打架的教训见归档的 ADR 0012 修订。
- 打扰只能有一个出口，所以沟通归 agent。

## 修订（2026-10-19，主人定）：给高级用户的本机端点

主人平时用自己的 oMLX 跑 pi agent，装了主控以后两边撞车：两份权重、两套内存判断，打字优先也护不住。主人定：交给主控做一个高级用户的本机端点，让 pi 指过去，不再单独跑引擎。理由是"体系里不应该有脱离主控的 LLM 运行实例"。

- 主控在 127.0.0.1 上开一个 OpenAI 兼容的端点，带密钥。默认关，入口在设置的高级选项里，不当普通用户功能宣传。
- 模型可以用主控自己的，也可以登记用户自己的本地模型（只读、只克隆，不改用户的文件和设置）。用户登记的不进评测和支持台账，质量由用户自己负责。
- 端点的请求算"用户在等"，排在后台任务前面，打字照旧最优先。加载大模型时由主控让路：先暂停后台任务、卸掉底座，放不下就答"放不下"，不硬挤。
- 安全照 ADR 0013 保留的那几条：只听本机，校验 Host，拒绝带 Origin 的网页请求，请求文字不落盘。
- 这是主控第一个 TCP 入口，luoke-core V1 里"没有 TCP 入口"那句随之改。

## 修订（2026-10-21）

- **日历由主控提供**：用户的日历和邮箱一样是数据源，不归某一个工具。主控提供一个很薄的本机日历接口（macOS EventKit：按时间段读事件、写一个事件并返回编号），系统的日历权限挂在主控名下、只请求一次，读写都要；"这封邮件的日程是不是已在日历里"这类判断留在各工具。配方里要登记哪些配件能用这个接口，第三方配件要调用时必须先得到用户的明确同意。beta1 之后做。
- **浏览器桥也由主控提供**（同日）：浏览器插件碰不到本机，要一个本机的中转。这个中转（native messaging host）放在主控里，不另做应用：插件经它把当前页的信息交给主控的任务抽取、调用主控的日历接口、往记忆写记录；以后 agent 在浏览器里的能力也走同一座桥。网页内容一律当不可信的数据，只接受固定格式。认页面、站点适配、什么时候提示用户这些业务留在插件里，插件是独立的项目。

## 修订（2026-10-24）

- **用户看到的「螺壳」是主控**：主控改名「螺壳」（`螺壳.app`，主人 10-23 定，见 ADR 0017 的 10-23 修订）。原来定给 agent 的名字「螺壳」（`螺壳.app`）和它撞了。
- **agent 并进「螺壳」**（主人 10-24 定）：用户只看到一个「螺壳」。agent 的对话、卡片、提示都从螺壳.app 的窗口和通知出去；agent 作为后台组件保留，分工不变，主动找用户说话仍然只走 agent。具体怎么接（窗口归谁画、通知以谁的名义发、agent 进程怎么起）在 beta1 之后由 luoke-agent 和 luoke-core 一起设计。agent 不再单独做 `螺壳.app`；开发版也不能再叫「螺壳（开发）」，那是主控开发版的名字。
- **agent 不在「应用」列表里单独勾选**（主人 10-25 定）：以后随螺壳一起装好，作为后台组件；设置里给一个「主动提醒」的开关，用户可以关掉。
