# 新增一个组件

团队成员要给螺壳加一个新组件（一个新的配件、工具或服务）时，照这一页走。社区和第三方的接入另行讨论（[luoke#1](https://github.com/luokelabs/luoke/issues/1)），不在这里。

## 先知道的几条底线

动手设计之前先读 [ARCHITECTURE.md](../ARCHITECTURE.md) 和 [顶层 ADR](adr/)。和新组件关系最大的几条：

- **推理都在主控**（ADR 0018）：组件不自带模型、不起自己的推理进程。要用模型，就在主控登记任务（生成、打分、嵌入等），经主控的 socket 调用。
- **数据不出用户自己的设备**（ADR 0013）：本机组件之间需要读什么都可以读；离开本机只能去用户自己的其他设备，中途不落在第三方。
- **分工**（ADR 0014）：理解在记忆，事情在各工具，主动找用户说话只走 agent。新组件如果要主动提示用户，经 agent 发出，不自己弹通知。
- **评测定开关**（ADR 0017）：每个用到模型的任务都要有评测集，在各内存档连过 3 遍才在那一档打开，失败一遍就关。

## 流程

### 1. 立项

写一页提案，说清这几件事：

- 做什么、给谁用、用户从哪里用到它；
- 要用主控的哪些能力（任务类型、大约多大的请求、多频繁）；
- 要读写记忆的什么，要别的组件提供什么；
- 和现有组件有没有重叠。

提案放在团队的私有仓库（`luokelabs/luoke-ops` 开 issue），由主人决定做不做、放在哪一层。

### 2. 建仓库

主人同意后，在 luokelabs 下建一个私有仓库，名字用 `luoke-<组件名>`。仓库里放自己的 `CLAUDE.md`（给在这个仓库工作的 Claude Code 会话看）、`CONTEXT.md`（组件自己的术语）和 `STATUS.md`（进度）。建仓库由主人或经主人同意后做。

### 3. 登记

往本仓库提一个 PR，新增注册页 `projects/luoke-<组件名>.md`，照其他注册页的结构写：

- **提供什么**：对用户、对别的组件的接口；
- **依赖谁**：主控的任务、记忆的接口等；
- **需求**：要别的组件新做的东西，每条写清要什么。

`luoke-top` 对照 ARCHITECTURE 和 ADR 审 PR，把结论交给主人；主人同意后合并，`luoke-top` 把新仓库作为子模块挂到本仓库。合并之后它就是正式的项目，之后改注册页照常只改自己那一页。

注册页是公开的：不写主机名、个人邮箱、用户数据和内部细节。

### 4. 对接

对别的组件的需求写进自己注册页的"需求"一节，再到对方的仓库开 issue 指过去。怎么做由对方的项目会话定；对方接下后写进它自己的注册页。两边谈不拢的交给主人。

要改分工、共同底线或项目之间的约定，在本仓库开 issue，由 `luoke-top` 和主人讨论后改顶层文档。

### 5. 进版本

- 配件按 [配件清单](https://luokelabs.github.io/luoke-atlas/) 的格式写清单（bundle id、版本、任务、空闲任务、数据目录等），用团队的 Developer ID 签名公证。
- 每个任务的评测集交给 luoke-core，由它放进配方、在三个内存档上评测。
- 开发期间可以用开发清单在实验室主控上调试；本机试用经主控的"本机放行"先用上，不用等内部版。
- 每天 20:00 的内部版会钉住各项目 main 的最新提交，新组件合并登记后也照此进版本。
